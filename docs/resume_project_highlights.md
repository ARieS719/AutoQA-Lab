## 版本 A：互联网 / 软件测开（电商主线）

> **AutoQA-Lab｜微服务全链路自动化测试与 AI 质效平台**（独立开发）｜[GitHub](https://github.com/ARieS719/autoqa-lab)

**项目描述**：面向高并发交易与异步通知场景构建的微服务测试工程基建，涵盖 FastAPI 白盒被测靶场、三层白盒接口自动化、Locust 性能压测与瓶颈调优闭环，并引入 DeepSeek-V3 实现失败归因、精准回归调度与断言自愈。

**全链路白盒接口自动化**：基于 FastAPI+MySQL+Redis 搭建被测微服务靶场（订单/秒杀/Webhook/消息队列四条链路）；使用 Pytest+YAML+Pydantic+Hypothesis 构建自动化框架，覆盖订单状态机 CAS 防重、Redis 分布式锁防超卖、MQ 最终一致性、Webhook 验签回调及 Fuzz 边界测试，实现「HTTP 响应 + 数据库状态 + 缓存/异步」三层白盒断言，32 项用例 100% 通过（含 200 组模糊数据），服务端代码覆盖率达 93.14%。

**高并发性能压测与瓶颈摸高**：基于 Locust 开展 100 并发压测（60 秒承接 8,900+ 请求），通过内存队列预热消除读库 I/O 干扰；以 Redis Lua 原子扣减取代应用层分布式锁、配合 MySQL 联合索引自愈解决秒杀锁竞争风暴，失败率由 76.07% 收敛至 0.00%，秒杀 TP99 由 3.4s 降至 480ms（-86%），混合链路吞吐由 75 提升至 151 req/s，全程零超卖。

**CI/CD 精准回归与 AI 提效**：基于 GitHub Actions+Docker Compose 搭建流水线，依次执行 Ruff 静态门禁、测试与覆盖率卡点（实测 93.14%，门禁 80%）、压测烟雾门禁与 Allure 报告发布；开发 Git Diff 变更分析调度器实现精准回归，并基于 DeepSeek-V3 驱动 OpenAPI 智能体自主测试与 SQL 白盒核验，结合 Pytest Hook 输出失败根因诊断与断言自愈补丁。

### 面试 1 分钟稿

> 这是我独立开发的测开工程。我先把被测系统写出来——一个 FastAPI 高并发交易靶场，订单、秒杀、支付回调、消息队列四条链路，然后为它建了完整的测试体系：接口契约、数据库落库、异步轮询三层断言，32 个用例加 200 组模糊数据，服务端覆盖率 93.14%，CI 里 80% 是硬门禁，不够就红。
> 最有意思的是压测调优：100 并发压秒杀，失败率 76%、TP99 到 3.4 秒。我顺着日志定位到分布式锁的竞争风暴——锁的吞吐追不上流量。后来把「检查+扣减+计数」改成 Redis Lua 一条脚本原子执行，TP99 降到 480 毫秒，失败率归零。这段经历让我想清楚了一件事：什么时候该用锁、什么时候该用服务端原子化，而不是背答案。
> 另外做了三个 AI 提效工具：失败日志自动归因、按 Git Diff 挑回归用例、坏断言自动修复，都做了无 Key 降级——CI 不依赖大模型可用性。

**高并发性能压测与瓶颈摸高**：基于 Locust 开展 100 并发压测（60 秒承接 8,900+ 请求），通过内存队列预热消除读库 I/O 干扰，定位并解决秒杀锁竞争风暴——以 Redis Lua 原子扣减取代应用层分布式锁，配合 MySQL 联合索引自愈，失败率由 76.07% 收敛至 0.00%，秒杀 TP99 由 3.4s 降至 480ms（-86%），混合链路吞吐由 75 提升至 151 req/s，全程保持零超卖。
